很久没用 C#，重新打开项目时，常见的感觉是：概念似乎还记得，但一写代码就要查语法；能看懂不少内容，却很难从零组织一个小功能。

这种情况适合从 **恢复语法手感 → 找回 C# 的核心机制 → 完成一个小项目** 开始。

本文面向以前用过 C#、近期主要使用 TypeScript 或 Cocos 的开发者。目标很具体：**不依赖教程，独立写出一个包含类型设计、数据保存和异步操作的小程序。**

## 一、先看完整学习路线 {#roadmap}

| 阶段 | 重点掌握 | 达到什么程度 |
|---|---|---|
| 基础语法 | 类型、变量、条件、循环、方法、集合 | 能把思路写成可运行代码 |
| 类型与对象 | `class`、`struct`、接口、属性、泛型、可空类型 | 能合理设计数据和行为 |
| C# 常用能力 | 委托、事件、Lambda、LINQ、异常、资源释放 | 能读懂和编写常见业务代码 |
| 运行机制 | 值复制、引用、装箱、GC、异步与线程 | 能解释代码为什么这样运行 |
| 工程实践 | 项目结构、NuGet、调试、测试、日志 | 能维护一个完整项目 |

恢复学习时，先用实际编码找出薄弱点，再回到对应阶段补知识。碰到某个语法忘记时，查清并立即应用；碰到行为解释不清时，单独写一个最小实验。

不必在第一轮同时学习所有新语法、运行时细节和应用框架。先恢复基本业务开发能力，再按项目需要扩展。

## 二、用七天找回开发手感 {#seven-days}

每天安排 **45～90 分钟**。如果时间不够，可以把一天的任务拆成两天；以完成练习为准。

| 时间 | 复习内容 | 当天动手任务 |
|---|---|---|
| 第 1 天 | 基本类型、方法、`List`、`Dictionary`、调试器 | 写一个物品列表，支持添加、删除和查找 |
| 第 2 天 | `class` / `struct`、属性、值复制与引用复制、`ref/out/in` | 用小实验验证“修改对象”和“替换参数”的区别 |
| 第 3 天 | 接口、泛型、组合、继承 | 定义 `IUsable`，实现药水等物品的使用行为，并为装备设计独立能力 |
| 第 4 天 | 委托、`Action`、`Func`、事件、Lambda | 背包变化时触发事件，让显示模块刷新 |
| 第 5 天 | LINQ、排序、分组、延迟执行 | 按品质筛选、按数量排序、按类型统计 |
| 第 6 天 | `async/await`、`Task`、异常、取消 | 异步读取物品配置，支持取消并处理失败 |
| 第 7 天 | JSON、文件操作、`using`、测试 | 保存和读取背包数据，验证几个关键规则 |

### 第一天从一个控制台项目开始

安装适合练习环境的受支持 .NET SDK，并准备支持 C# 调试的编辑器或 IDE。如果最终目标是 Unity，后续还需要核对 Unity 所支持的 C# 和 .NET API 范围。

```bash
dotnet new console -n CSharpRefresh
cd CSharpRefresh
dotnet run
```

先让程序运行起来，打断点、单步执行、观察集合和对象的变化。第一版只要能在控制台里操作物品，就已经足够。

### 每天的学习节奏

1. **回忆 10 分钟**：先凭记忆写，找出真正卡住的地方。
2. **补知识 15～25 分钟**：针对当天的卡点查文档、读笔记。
3. **编码 20～40 分钟**：把知识点用进小项目。
4. **复盘 5～10 分钟**：记录一个容易混淆的概念，以及验证它的最小例子。

学完一个主题后，尝试关闭参考材料，重新写出关键部分。能独立复现，才说明知识已经恢复到可用状态。

## 三、从 TypeScript 切回 C#，优先补哪些差异 {#differences}

### 1. 类型系统：编译期检查与运行时类型

TypeScript 的多数类型信息在编译后擦除；C# 的类、接口和泛型具有相应的运行时类型机制。

对普通类和接口来说，C# 主要采用名义类型关系：两个类型即使成员形状一样，也不会仅因此自动兼容。复习时重点理解 `implements` 风格的契约关系在 C# 中如何表达，以及接口和泛型约束怎样参与设计。

### 2. 值类型与引用类型：先弄清行为

- `struct` 赋值时默认复制值；结构体中如果包含引用类型字段，复制的仍是这些字段中的引用。
- `class` 变量赋值时复制引用，两个变量可能指向同一个对象。
- 默认参数传递是按值传递。传入引用类型变量时，复制的是引用。
- `ref` / `out` 允许方法通过参数修改调用者的变量；`in` 提供只读引用参数。

最值得练习的三个问题：

1. 方法内修改 `obj.Count`，调用者能看到吗？
2. 方法内执行 `obj = new Item()`，调用者的变量会被替换吗？
3. 把参数改成 `ref Item obj` 后，第二个问题的结果如何变化？

### 3. 属性与字段

重点区分 `get/set`、`private set`、`init` 和 `readonly`。

```csharp
public class ItemStack
{
    public string ItemId { get; init; } = "";
    public int Count { get; private set; }

    public void Add(int amount)
    {
        if (amount <= 0)
            throw new ArgumentOutOfRangeException(nameof(amount));

        Count = checked(Count + amount);
    }
}
```

这个例子中，外部可以在初始化时设置 `ItemId`，但不能直接修改 `Count`。增加数量要通过 `Add`，由方法维护规则。

`readonly` 字段限制的是字段赋值；如果字段里保存的是可变对象的引用，它并不会自动冻结那个对象。

### 4. 委托与事件

可以先把 `Action`、`Func` 理解为有明确签名的可调用对象，再学习 `event` 的边界。

- `Action<T>`：接收参数，没有返回值。
- `Func<T, TResult>`：接收参数并返回结果。
- `event`：用于发布通知，外部通常只能订阅和取消订阅，不能像普通委托字段那样任意覆盖或触发。

在练习中，让背包模块发出变化通知，让显示模块订阅。随后练习取消订阅，理解对象生命周期与事件引用的关系。

### 5. LINQ 与延迟执行

`Where` / `Select` 很像 TypeScript 中的 `filter` / `map`，但对 `IEnumerable<T>` 使用的许多 LINQ 查询会延迟执行。

```csharp
var numbers = new List<int> { 1, 2, 3 };
var query = numbers.Where(n => n > 1);

numbers.Add(4);
Console.WriteLine(string.Join(", ", query)); // 2, 3, 4

var snapshot = query.ToList();
numbers.Add(5);
Console.WriteLine(string.Join(", ", snapshot)); // 2, 3, 4
```

这里的 `query` 保存的是查询逻辑，枚举时才读取集合。`ToList()` 会在调用时枚举并生成结果列表；如果元素是引用类型，列表中保存的仍是对象引用，并不等于深拷贝。

复习时要能回答：查询什么时候执行？重复枚举会不会重复执行逻辑？哪些地方需要物化结果？

### 6. 异步模型

`Task` 可以帮助你用熟悉的 Promise 思路理解异步结果，但 C# 还需要补上线程、同步上下文和 `CancellationToken`。

- `async` 不代表自动开启新线程。
- `await` 不保证一定挂起；等待对象已经完成时，可以直接继续执行。
- 异步 I/O、线程池上的 CPU 计算和并行处理是不同问题。
- 取消通常是协作式的：要把 `CancellationToken` 传给支持取消的操作。
- 异常需要在合适边界捕获，避免无意中遗忘返回的 `Task`。

第一轮先写出一个可等待、可取消、能处理失败的配置加载方法，再研究更复杂的调度机制。

## 四、用背包管理器串起知识点 {#project}

熟悉游戏开发时，背包系统是很合适的练习题：业务含义容易理解，又能覆盖类型、集合、事件和持久化。

### 最小功能清单

- 按物品 ID 添加、扣除和查询数量。
- 数量不足时扣除失败，背包数据保持一致。
- 支持物品名称、类型和品质等配置。
- 背包变化时通知显示模块。
- 支持筛选、排序和统计。
- 能保存为 JSON，并从文件恢复。
- 读取失败、文件损坏或操作取消时，给出清晰结果。

可以从以下几个角色开始，不必一开始就拆出大量文件：

| 角色 | 负责什么 |
|---|---|
| `ItemDefinition` | 物品 ID、名称、类型等配置 |
| `ItemStack` | 某个物品的数量与局部规则 |
| `Inventory` | 添加、扣除、查询和变化通知 |
| `InventoryStorage` | JSON 与文件读写 |
| `Program` | 控制台输入和结果展示 |

保存时优先考虑独立的存档数据结构，再通过明确的加载流程还原业务对象。不要默认带私有 setter 的业务对象可以直接按预期反序列化。

### 至少验证这些规则

- 同一物品重复添加后，数量正确累加。
- 扣除超过现有数量时，不会留下负数或半完成状态。
- 无效物品 ID 和非正数量有明确处理方式。
- 保存再读取后，关键数据保持一致。
- 配置加载失败时，不会清空原本正常的数据。
- 取消操作可以被识别和妥善处理。

项目不必复杂，但每个行为都应当能解释、能验证。

## 五、现有笔记怎么配合使用 {#reading}

推荐按这个顺序复习：

1. 先读 [TS 与 C# 类型系统 & 传参笔记](/posts/ts-csharp-types-and-parameters/)，连接熟悉的 TypeScript 与 C# 概念。
2. 再用 [编程语言七大基础维度 · C# 版](/posts/csharp-seven-fundamentals/)逐项自查，标出已经熟悉、语法生疏和理解不清的部分。
3. 对值、对象和参数传递仍有疑问时，补读 [TypeScript 中的值类型与引用类型](/posts/typescript-value-and-reference-types/)。
4. 每读一个主题，自己写一个最小实验：先预测输出，再运行或调试验证。
5. 最后把实验里的知识用进背包管理器。

可以利用文章批注记录卡点，再到 [我的批注](/annotations/)集中整理。复习记录尽量写成“问题 + 实验 + 结论”，方便下次快速找回。

## 六、容易记错的几个概念 {#pitfalls}

复习旧笔记时，尤其要留意把简化描述误记成绝对规则。

### 值类型不一定存放在栈上

值类型的存放位置取决于上下文。对象字段、数组元素和装箱后的值，都可能涉及堆内存。首先理解赋值和参数传递时的复制行为，再研究具体运行时的存储实现。

### `Span<T>` 不等于栈上分配的数组

`Span<T>` 是连续内存的视图，可以引用数组、栈内存等不同来源的内存。`AsSpan()` 创建视图不等于把原数组搬到栈上。

### 引用类型默认传参仍然可能产生副作用

默认传递引用的副本，方法仍然可以通过它修改共享对象内部的数据。使用默认传参并不意味着方法天然没有副作用。

### 检查条件应当发生在危险操作之前

例如除法练习，必须先判断除数是否为零，再执行运算。运算后才返回 `b != 0`，无法避免已经发生的异常。

### Lambda、局部函数和顶级语句也要认识

学习类和方法之后，应继续了解局部函数、Lambda 与顶级语句。它们让 C# 的代码组织方式更加灵活，不宜把所有函数写法都简单等同于手写类成员。

## 七、如何判断已经捡起来 {#checklist}

可以用下面的清单验收。重点是能独立完成，并说清楚原因。

- [ ] 能解释对象传参代码的输出，区分修改对象、重新赋值和 `ref`。
- [ ] 能独立设计一个接口，并写出两个不同实现。
- [ ] 能根据用途选择 `List`、`Dictionary` 或 `HashSet`。
- [ ] 能正确订阅和取消订阅事件。
- [ ] 能编写筛选、排序、分组查询，并说明什么时候执行。
- [ ] 能写出支持取消和错误处理的异步方法。
- [ ] 能保存和读取数据，并处理无效输入与损坏文件。
- [ ] 能用断点和变量观察定位问题。
- [ ] 能为关键业务规则编写验证用例。

如果多数任务都能完成，就可以进入实际项目，在使用中继续补齐细节。

## 八、恢复基础以后往哪里走 {#next}

### 游戏开发方向

继续学习 Unity 的组件生命周期、资源管理、事件、序列化，以及性能和内存分配。关注目标 Unity 版本实际支持的语言和 API，控制台项目中可用的功能不一定能原样使用。

### 服务端方向

继续学习 ASP.NET Core、依赖注入、HTTP 接口、数据库、日志与测试。先完成一个小型 API，再逐步处理身份验证、部署和性能问题。

### 今天就开始的第一步

创建一个控制台背包程序，**凭记忆写半小时，把卡住的点记下来**。

这份卡点清单会帮助你决定下一步复习什么。持续完成“写代码 → 发现问题 → 查证 → 再写一次”的循环，C# 的开发手感就会逐步恢复。
